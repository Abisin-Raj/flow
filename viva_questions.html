50 Viva Questions & Answers on Flow EDR

Comprehensive Technical Defense Document for the Flow Project

Part 1: Architecture & Project Overview

1) What is the Flow EDR project?

Flow is a comprehensive Endpoint Detection and Response system built in Python, utilizing a Django backend for core security logic and database management, paired with a PyQt5 graphical desktop frontend.

2) What are the main components of Flow?

It consists of a Desktop UI, a Django core backend, a packet sniffer, a static file scanner, a firewall auto-mitigator, and local threat intelligence databases.

3) Why did you choose Python for this project?

Python offers rapid development and a vast ecosystem for network and security tools (like Scapy for sniffing), easily bridged with robust frameworks like Django (backend) and PyQt5 (frontend).

4) How does the frontend communicate with the backend?

The PyQt5 frontend imports Django models directly and queries the local database running on the host machine. It operates completely locally without relying on REST APIs over HTTP.

5) What is the specific role of Django in this architecture?

Django serves as the Object-Relational Mapper (ORM), securely managing the database schema for alerts, connections, and settings, while providing utility structures and an admin interface.

6) Why use PostgreSQL instead of SQLite for this project?

PostgreSQL handles concurrent high-volume inserts (like thousands of packets from the sniffer) far better than SQLite, which locks the entire database file during write operations.

7) Does the application use any external cloud APIs for threat detection?

No, Flow is designed to be fully self-contained and offline. It uses bundled JSON and binary databases locally to ensure data privacy and zero network latency during incident detection.

8) How is database concurrency managed between the UI and backend background services?

PostgreSQL inherently handles connection concurrency cleanly. Additionally, the backend uses a local, TTL-based thread-safe cache (`settings_api`) to keep database trips to a minimum for frequently accessed settings.

9) What are "AppSettings" in the Django model?

They are a simple Key-Value store table in the database used to persist configuration states (like detector sensitivity or service toggles) across computer restarts.

10) What role do Django signals play in Flow?

We use `signals.py` to attach listeners to model `post_save` events. This allows decoupled code to react instantly when a new malicious alert triggers, prompting the UI or the auto-mitigator.

Part 2: Network Monitoring & Threat Detection

11) How does Flow perform network packet sniffing?

It utilizes the Scapy library and native Python sockets to intercept raw network traffic directly on the host's networking interface in the background.

12) What is the difference between the `packet_sniffer` and `light_sniffer` modules?

The packet sniffer performs deep packet inspection and detailed parsing. The light sniffer sacrifices deep inspection to focus purely on high-speed flow metrics and metadata extraction.

13) How are reverse shells detected in Flow?

By analyzing connection patterns, checking connections initiated toward suspicious external ports, and correlating those network flows with host-level process anomaly metrics.

14) Explain how Flow detects ARP spoofing attacks.

The `arp_mitm_detector` monitors ARP replies on the local network. It detects inconsistencies by recognizing when a MAC address abruptly changes its mapping for a known critical IP, such as the gateway router.

15) How is port scanning identified by the module?

The system tracks the number of distinct destination ports a single source IP attempts to touch within a configured short time window (e.g., 20 ports in 10 seconds).

16) What is the role of the `tx_spike_detector.py`?

It monitors outbound (transmit) traffic volumes and logs alerts for sudden, massive spikes in data transfer, which is a strong indicator of unauthorized data exfiltration.

17) How does the system map network connections to local processes?

It uses the `proc_net_parser.py` module to parse Linux `/proc/net/tcp` and `/udp` structures, mapping socket inodes to local process IDs (PIDs) incredibly fast without heavy utilities like `netstat`.

18) How are DNS queries monitored?

The DNS monitor grabs traffic destined for port 53, extracts the domain payload from the DNS request, and evaluates the domain name against the local reputation database.

19) What threat intelligence databases are used locally?

Flow packages static JSON feeds (`malware_db.json`, `reputation.json`) to silently check file hashes and IPs without leaking data to external APIs.

20) How does the local IP reputation system work?

Every inbound and outbound IP is passively checked against the internal `reputation.json`. If an IP matches a known malicious node, a high-severity alert triggers immediately.

21) Provide an example of how Flow identifies a suspicious port.

Configurations contain lists of notoriously abused ports (e.g., 4444, 5555, 1337). The `rare_port_detector` raises an alert if an outbound connection targets one of these ports anomalously.

22) What are the common challenges of raw packet sniffing in Python?

Python’s Global Interpreter Lock (GIL) and general execution speed limit throughput. To compensate, BPF (Berkeley Packet Filter) syntax is applied at the OS level to drop irrelevant traffic before it reaches Python.

Part 3: File Scanning & System Monitoring

23) How does the `file_scanner` module detect malware?

It cryptographically hashes files (e.g., MD5, SHA256) upon creation or periodically and checks if those hashes exist in the `malware_hash_feed.json` indicator list.

24) What is TLSH and why is it used in file scanning?

Trend Micro Locality Sensitive Hash (TLSH) is a fuzzy hashing technique. It allows Flow to detect slight variations of known malware that have been mutated just enough to bypass exact cryptographic matching.

25) Explain the difference between Quarantine and Deletion in the context of Flow.

Quarantine safely isolates a suspicious file by moving it to a non-executable directory and stripping its execution permissions for forensic preservation. Deletion completely wipes the file, losing potential evidence.

26) Describe the `folder_watcher.py` mechanism.

It relies on file system event monitoring (such as `inotify` on Linux) to detect unauthorized file creations or modifications within explicitly protected directories in real time.

27) What does the `persistence_watcher.py` look for?

It monitors modifications in critical startup scripts, `cron` jobs, or systemd services to catch malware intending to persistently run after a system reboot.

28) How does Flow ensure it doesn't overburden the host CPU?

The deep scanners make use of optimized asynchronous queues. Furthermore, system utilization is actively constrained and monitored via the `collectors.py` and `metrics.py` resources managers.

Part 4: Mitigation & Contextualization

29) How does Flow automatically mitigate threats?

When alerts reach a critical severity threshold, the `auto_mitigator` works with the `firewall` module to dynamically inject DROP rules for the offending IP into the OS firewall (`iptables` or `ufw`).

30) What is a "dry run" mode in the firewall settings?

Enabling this mode causes Flow to log the blocking decisions it *would* make to the database without actually writing active blocking rules to the OS firewall, ensuring safety during testing.

31) What is the purpose of the `block_policy.py` and `unblock_policy.py`?

They codify the rules dictating which IPs get banned, track the ban duration, and handle the mechanics of automatically revoking the ban when the penalty time expires.

32) How are safe IPs protected from being blocked by the mitigator?

The `protected_ips.py` maintains hardcoded and user-defined allow-lists, and the settings API verifies if an IP belongs to a private subnet, bypassing auto-mitigation logic for trusted sources.

33) What happens during an automated unblock?

A scheduled maintenance loop identifies expired `BlockedIP` records in the database, sends a command to `iptables` to remove the matching rule, and then deletes the database record to restore connectivity.

34) How is geolocation handled completely offline?

By utilizing the MaxMind `GeoLite2-City.mmdb` binary database file. The Python library queries this highly optimized local binary to map IP addresses to geographic metadata instantly.

35) Why do we need geolocation for IP addresses in an EDR?

Adding location context assists analysts in quickly spotting anomalies like impossible travel distances, outbound connections to notoriously hostile foreign regions, or targeted geography-based infiltration.

36) How does Flow handle high rates of repeated alerts?

It uses a cooldown logic variable (`detector.cooldown_seconds`) within the `alert_engine`. Subsequent identical events inside this time window are logically grouped or suppressed to prevent UI alert fatigue.

37) What is `alert_explain.py` for?

It leverages algorithmic or heuristic text generation to create natural language, plain-English explanations for complex alerts, significantly accelerating triage for junior security analysts.

38) In the context of Flow, what is the meaning of a "Severity" score?

Severity is a normalized qualitative metric (usually 1 to 5 or Low to Critical) assigned to alerts based on impact context, allowing defensive automation to surgically trigger only on the most critical issues.

39) How can the user adjust detector sensitivity?

Through the desktop UI Settings tab, which invokes `settings_api.py` to seamlessly modify dynamic thresholds like `brute_window` sizes or `tx_spike_threshold_mb` on the fly.

Part 5: UI, Desktop Integration, & Lifecycle

40) How does the UI visually represent alerts?

The `alerts_widget` provides an interactive tabular grid, while the `dashboard_graphs_widget` translates statistical trends into readable bar charts and severity tracking timelines.

41) What does the `top_attackers_widget` do?

It cross-examines recent blocked connections and alerts to graphically display the top ten most frequent offending IP addresses aggressively hammering the endpoint.

42) How does Flow provide system-level OS notifications?

The `notification_manager` pushes native desktop alerts (like Linux DBUS notifications) directly to the user environment, avoiding the need for the user to keep the Flow dashboard visibly open.

43) Explain the role of `alert_watcher.py` in the frontend.

It instantiates a QThread background process that asynchronously polls the Django database for newly inserted alerts, updating the UI dynamically without locking the main frontend render thread.

44) What is the purpose of `export_service.py`?

It retrieves thousands of database records (Connections or Alerts) and cleanly maps them into sanitized CSV files within the user's home folder for subsequent external reporting or graphing tools.

45) What command-line automated setups are provided in the `scripts` directory?

Installation bash scripts (e.g., `setup_postgres.sh`, `fix_postgres_auth.sh`) entirely automate the heavy lifting of provisioning the database environment, handling system permissions natively.

46) Why export the application as Debian/RPM tracking packages (`packaging/` tab)?

Providing a compiled specification `.spec` and `.service` files enables seamless enterprise rollout. It allows Linux operating systems to natively track the software dependencies and boot Flow sequentially as an OS daemon.

47) How is the desktop UI aesthetically styled?

It leverages PyQt's integrated stylesheet engine (QSS), mapped heavily in `ui_helpers.py`, allowing us to assign sleek dark-mode, futuristic palettes consistent with modern security posture tools.

48) What purpose does `cleanup.py` and management commands like `cleanup_old_data` serve?

Endpoints deal with vast telemetry metrics. These cron-triggered functions continually prune connection logs and harmless records older than a dynamic `retention.days` threshold to prevent disk exhaustion.

49) How does Flow handle the identification of a host's own Local IP address dynamically?

The local network interface API logic binds a phantom UDP socket briefly to standard external route (e.g. 8.8.8.8) simply to query the OS routing table on which internal Interface/IP it preferred.

50) If you were to scale Flow, what would be the next architectural evolution?

Introducing architectural distribution: decoupling the local PostgreSQL structure to ship raw metrics into a centralized SIEM server (like ELK/Splunk), allowing a single SOC interface to monitor fleets of Flow agents network-wide.
